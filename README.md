# Trae 每日自动签到

**当前版本：v1.1** ｜ [更新记录](#更新记录)

Trae（字节 Trae Work）每日积分自动领取。**零第三方依赖**，只用 Python 标准库，NAS / 青龙面板 / GitHub Actions 都能跑。

> ⚠️ 这是第三方逆向脚本，与 Trae 官方无关，可能违反服务条款，接口随时可能失效。请自行评估风险后使用。

---

## 先看两个硬约束

这两条决定了这个项目**能不能满足你的需求**，请先看完再动手。

### 1. 每个账号都需要一个「真实设备号」

签到请求要带 `x-device-id`，而这个号**必须是 Trae 客户端在服务器上注册过的**——它写在客户端 `storage.json` 的键名里：

```
iCubeAuthInfo://icube-dc:3124143766407755
                          ^^^^^^^^^^^^^^^^ 这一段数字
```

**自己编一个数字是不行的。** 同账号同时刻的对照实测：

| 发送的设备号 | `status` 的 `did_checked_in` | `claim` 返回 |
|---|---|---|
| 自动生成的数字 | `false` | **9074** |
| 客户端真实 Aha 号 | `true` | **9095**（通过设备检查） |

OAuth 登录**不会**把设备号注册成可信设备，所以生成号注定失败。真实号只能从**装了 Trae 客户端的机器**上取（用 `01_get_device_id.py`）。

> **位数不固定，不要按 16 位去卡。** 多数机器是 16 位，但也有 **15 位**的真实号——早期版本把校验写成"必须 16 位"，导致 `01_get_device_id.py` 报"里面没有设备号"，人以为是客户端没登录。服务端认的是"客户端注册过的那串数字"，跟位数无关（脚本现在只要求是一串十进制数字）。

### 2. 一个设备号一天只能签一个账号

签到限额是按**设备**算的，不是按账号：

```
claim → {"code":9095,"message":"当前设备今日已经签到，请明日再来哦～"}
                                ^^^^ 主语是"设备"
```

多个账号共用同一个设备号，只有第一个能签成，其余全部 9095。

> **推论：N 个账号想每天各签一次，就需要 N 台装过 Trae 客户端的机器。**

先问自己一句：

- **只签 1 个账号** → 完全没问题，一台机器取个设备号就行 ✅
- **签多个账号，且有对应数量的机器**（虚拟机也算）→ 可行 ⚠️
- **签多个账号但只有一台机器** → **做不到**，一天只能签一个

## 文件结构

```
trae-checkin/
├── 01_get_device_id.py     ① 取真实设备号（在装了客户端的机器上跑）
├── 02_login.py             ② 登录拿 token（在跑签到的机器上跑）
├── 03_checkin.py           ③ 签到（每天跑这个）
├── 04_credit_monitor.py    ④ 积分监控（只读，可选）
├── trae_core.py            共用实现模块 —— 不直接运行
├── config.json             设置，一般不用改
├── accounts.example.json   账号模板
├── accounts.json           账号（登录后生成，手动补 deviceId）
├── .github/workflows/
│   └── checkin.yml         GitHub Actions 定时签到（可选，见下文）
└── logs/                   运行日志，自动生成
```

环境要求：**Python 3.8+**，无需 `pip install` 任何东西。

> `trae_core.py` 没有编号，是因为 **Python 不能用数字开头的模块名做 `import`**（`import 03_checkin` 是语法错误）。它是被 01~04 共用的实现，不需要单独运行。

## 快速开始（三步）

### 第 1 步：取真实设备号

在**任何一台装了 Trae 客户端、并且登录过**的机器上跑（本机或朋友电脑都行）：

```bash
python 01_get_device_id.py
```

```
  客户端: C:\Users\a\AppData\Roaming\Trae CN\User\globalStorage\storage.json
  已升级为 Aha 号: true
  >>> 设备号: 1234567890123456
```

记下这个号。**这台机器以后就是"这个账号的机器"**，别的账号不能再用它的号。

这个脚本是**独立单文件**，不依赖本项目其它文件——可以直接发给朋友让他自己跑。

### 第 2 步：在跑签到的机器上登录

在 NAS / 青龙那台机器上（**不需要**装 Trae）：

```bash
python 02_login.py --device-id 1234567890123456
```

会打印一条登录链接。脚本**不会**自动打开浏览器（无头环境用不了），需要你手动把链接复制到浏览器打开，用手机号验证码登录，然后**把地址栏里那条打不开的 `127.0.0.1` 链接整条复制回来**粘贴。

链接打不开是正常现象，不需要端口转发。

登录成功后写入 `accounts.json`，设备号也一并写进去了。

### 第 3 步：签到

```bash
python 03_checkin.py
```

如果希望程序自己常驻、每隔 **24 小时** 自动执行一次：
```bash
python 03_checkin.py --24h
```

24 小时模式以程序启动时间为基准，每 24×60×60 秒执行一轮；程序会一直运行，按 `Ctrl+C` 可停止。

青龙定时建议（如果使用青龙，就继续由青龙负责每天启动一次；不需要同时使用 `--24h`）：

```cron
23 3 * * *    python3 /ql/data/scripts/trae/03_checkin.py
```

## 部署到 GitHub Actions

不用自备服务器、不用装 Python，GitHub 免费给你跑。

### 先理解一件事：状态必须跨次保留

`refreshToken` 是**轮换链**——每次续期都会产生新值，旧值随即作废。而 Actions 的工作目录是**一次性的**，跑完就丢。所以续期后的新 token 必须存到仓库外面，否则**第二次运行就会拿一份已经作废的 token 去登录，必然失败**。

本仓库的做法是用 Actions 自带的缓存（`actions/cache`）保留 `.trae_token_cache.json`。脚本里的 `apply_cache()` 会拿缓存中较新的 token 覆盖静态配置——这个机制本来就是为"配置写死、不会变"的场景准备的（青龙的环境变量同理）。

> **不要为了"持久化"把 `accounts.json` 提交进仓库。** 那等于公开你的 refreshToken。脚本也不需要它 —— 账号从 `TRAE_ACCOUNTS` 读，续期结果落在缓存里。

### 操作步骤

**1. 把仓库 Fork 到你自己的账号下**（或者直接用你自己的仓库）。

**2. 加 Secret。** `Settings` → `Secrets and variables` → `Actions` → `New repository secret`：

| Name | Value |
|---|---|
| `TRAE_ACCOUNTS` | `accounts.json` 里 `accounts` 数组那一整段 JSON |

要推送到手机就再加（都选填，含义见[设置放哪](#设置放哪)）：

| Name | 对应 |
|---|---|
| `QYWX_TOKEN` | 企业微信机器人 key |
| `PLUSPLUS_TOKEN` | PushPlus token |
| `TRAE_WEBHOOK` | 自定义 webhook 地址 |

**3. 启用工作流。** `Actions` 标签页 → 左侧选 `Trae 每日签到` → 点 `Enable workflow`。

**4. 手动跑一次验证。** `Run workflow` → 看日志输出。

**5. 之后每天自动跑。** 想改时间就编辑 `.github/workflows/checkin.yml`。

### cron 写的是 UTC，不是北京时间

**这点和青龙不一样**（青龙跟随容器时区）。GitHub 的 `schedule` 一律按 UTC，北京 = UTC+8，所以要**减 8 小时**：

| 想在北京时间 | cron 写 |
|---|---|
| 00:23 | `23 16 * * *` |
| 03:23 | `23 19 * * *` |

仓库自带的配置是 `23 16 * * *`（= 北京时间 00:23）。

另外两个 Actions 特有的行为要知道：

- 定时任务在高峰期**可能延迟几分钟到十几分钟**才真正触发，不保证准点
- 公开仓库的 Actions **完全免费**；私有仓库每月有免费额度（个人账号 2000 分钟），这个任务一次一两分钟、一天一次，一个月约 60 分钟，够用

### 这个方式的三个限制

1. **设备号还是得自己取。** Actions 跑在 GitHub 的机器上，那台机器没装 Trae，`01_get_device_id.py` 用不上。设备号必须先在你自己电脑上取好，填进 `TRAE_ACCOUNTS` 里对应账号的 `deviceId`。
2. **多账号需要多个真实设备号。** 一个设备号一天只能签一个账号，这个限制不会因为换到 Actions 就消失。有几个账号就要有几个来自不同机器的真实号，配齐了照样能跑；只有一个号的话，也只能签一个账号。
3. **缓存丢了就会失败。** Actions 缓存 7 天没人访问会被清掉。如果工作流连着超过一周没有成功运行，恢复不到缓存就会退回 `TRAE_ACCOUNTS` 里那份旧 token，需要重新 `02_login.py` 登录一次并更新 Secret。

> 附带的一个好处：失败时 GitHub 会给你发邮件。

### 工作流文件长什么样

完整内容在 `.github/workflows/checkin.yml`。有一段是**关键**，不能省：

```yaml
      # refreshToken 每次续期都会产生新值、旧值作废，而 Actions 的工作目录
      # 是一次性的。所以必须把续期后的 token 用缓存带到下一次运行。
      - name: 恢复 token 缓存
        uses: actions/cache@v5
        with:
          path: .trae_token_cache.json
          key: trae-token-${{ github.run_id }}
          restore-keys: |
            trae-token-
```

`key` 里带 `run_id` 是为了保证每次都写入一份新缓存（同名缓存不可覆盖），`restore-keys` 负责在下次运行时取回最近的那一份。

**这段删掉的后果**：第一次运行正常，但 token 已经续期并轮换；第二次运行拿到的还是旧的 `TRAE_ACCOUNTS`，那份 refreshToken 已经作废，直接失败。

## 脚本说明

### `01_get_device_id.py` — 取真实设备号

```bash
python 01_get_device_id.py             # 打印本机设备号
python 01_get_device_id.py --json      # 机器可读输出
```

**纯读本地文件：不联网、不解密、不碰任何 token。** 设备号就在键名里，连解密都不需要。

### `02_login.py` — 登录拿 token

```bash
python 02_login.py --device-id 1234567890123456   # 登录（必须带设备号）
python 02_login.py --checkin                      # 登录后立刻签一次
python 02_login.py --list                         # 查看已有账号
python 02_login.py --import FILE                  # 合并别人的 accounts.json
```

**`--device-id` 不能省。** 不传的话脚本会自己生成一个号，而生成号注定 9074——现在它会明确告诉你这一点，而不是让你签到失败后才发现。

登录产生的是一条**独立于桌面客户端**的会话链，两边互不影响——本机照常开着客户端用，不会因此被挤下线（详见常见问题里的「脚本会不会把我的 Trae 客户端踢下线」）。

### `03_checkin.py` — 签到

```bash
python 03_checkin.py          # 单次签到
python 03_checkin.py --24h   # 常驻，每 24 小时签到一次
```

行为：

- 先查状态（免费请求），已签到的不发领取请求
- 当日已成功的账号，之后运行零请求
- 遇到 9074 **不重试** —— 那是服务端容量门 / 设备号问题，当场连轰没用，记冷却后交给下一轮 cron 补签
- 账号没有设备号时**直接报「缺设备号」**，而不是去签一个注定失败的请求

### `04_credit_monitor.py` — 积分监控（只读）

```bash
python 04_credit_monitor.py           # 查询并推送
python 04_credit_monitor.py --local   # 只看终端输出
```

```
📊 Trae 积分监控（只读）2026-09-28 08:27
  💰 账号1：总额 1,550 · 已用 651.12 · 剩余 898.88
```

只调查询接口，**绝不发起领取请求**，也不写当日状态文件，可以和签到脚本任意交叉运行。

## 账号放哪

优先读脚本同目录的 `accounts.json`。模板见 `accounts.example.json`：

```bash
cp accounts.example.json accounts.json    # Linux / macOS
copy accounts.example.json accounts.json  # Windows
```

格式（三个账号共用一个文件的示例）：

```json
{
  "accounts": [
    {
      "name": "我的主号",
      "uid": "1000000000000001",
      "deviceId": "1234567890123456",
      "region": "CN",
      "accessToken": "",
      "refreshToken": "02_login.py 登录后自动写入"
    },
    {
      "name": "我的小号",
      "uid": "1000000000000002",
      "deviceId": "1111111111111111",
      "region": "CN",
      "accessToken": "",
      "refreshToken": "02_login.py 登录后自动写入"
    },
    {
      "name": "朋友A",
      "uid": "1000000000000003",
      "deviceId": "2222222222222222",
      "region": "CN",
      "accessToken": "",
      "refreshToken": "02_login.py 登录后自动写入"
    }
  ]
}
```

> ⚠️ 上面第 2、3 个 `deviceId` 是**占位数字**，必须换成各自机器上 `01_get_device_id.py` 取到的真实号，而且**三个号不能相同**。

| 字段 | 必填 | 说明 |
|---|---|---|
| `refreshToken` | ✅ | 由 `02_login.py` 写入 |
| `deviceId` | ✅ | **客户端真实 Aha 号**，由 `01_get_device_id.py` 取得 |
| `uid` | 建议 | 账号唯一键，也用于去重 |
| `accessToken` | 否 | 留空，脚本会自动用 `refreshToken` 换取 |
| `name` / `region` | 否 | 备注 / 默认 `CN` |

青龙也可以用环境变量 `TRAE_ACCOUNTS`（填上面 `accounts` 数组的内容），效果相同。

> **不要给多个账号填同一个 `deviceId`** —— 一天只能签一次，第二个起必然 9095。

## 设置放哪

脚本同目录的 `config.json`。**一般不用改**，默认值就能工作。只有两种情况需要动它：

**1. 配置推送**（最常见）

```json
{
  "notify": {
    "qywxToken": "企业微信机器人 key",
    "plusplusToken": "PushPlus token",
    "webhook": "自定义 webhook 地址"
  }
}
```

三项都留空就只打印到终端，不推送。

**2. 要调行为**

| 键 | 默认 | 说明 |
|---|---|---|
| `reqSource` | `2` | 签到请求体字段，**别改** |
| `claimTries` | `1` | 单轮领取次数。9074 不重试，交给后续 cron |
| `cooldownMin` | `30` | 9074 后的冷却分钟数 |
| `gapMin` / `gapMax` | `5` / `12` | 账号之间的间隔秒数 |
| `refreshMarginH` | `2` | token 剩余有效期低于几小时就续期 |
| `jitter` | `true` | 启动随机抖动 0~15s |
| `noProxy` | `true` | 强制直连，不走系统代理 |
| `log` | `true` | 写日志文件 |
| `only` | `""` | 只跑指定账号：序号 / uid / 名字 |

> 设备号**不在** config.json 里配——必须逐个账号写在 `accounts.json` 的 `deviceId`。做个"全局默认设备号"会让所有账号共用一个号，那是错的。

用记事本或 PowerShell 保存 `config.json` 会带上 UTF-8 BOM —— 脚本已做兼容。文件本身写错了会打印警告并退回默认值，不会崩。

## 多账号 / 帮朋友跑

### 每个账号配一套

对每个要签的账号：

| 步骤 | 在哪做 | 做什么 |
|---|---|---|
| 1 | 该账号对应的一台机器（装了客户端） | 跑 `01_get_device_id.py`，把设备号抄下来 |
| 2 | 跑签到的机器 | `02_login.py --device-id <上一步的号>` 登录 |
| 3 | 跑签到的机器 | 检查 `accounts.json` 里这个账号的 `deviceId` 对不对 |

**一台机器只能服务一个账号**，因为一个设备号一天只能签一次。

### 帮朋友跑

可行，但**朋友必须有一台装过 Trae 客户端的机器**：

1. 把 `01_get_device_id.py` 发给朋友（单个文件，独立运行），让他在自己电脑上跑，把设备号告诉你
2. 你在跑签到的机器上 `02_login.py --device-id <他的设备号>`，生成一条独立会话
3. 朋友自己**不要再跑脚本**（他照常开着客户端没问题，那是另一条链）

⚠️ 如果朋友本来就有 Trae 客户端、平时会开，那他自己点一下签到就行，其实不需要你代签。

⚠️ 用 `02_login.py` 生成的是**独立会话链**，不要拿朋友客户端 `storage.json` 里的 token（那会和客户端共用同一条链、互相踢下线）。**token 要"独立"，设备号要"真实"——来源正好相反。**

### 合并别人给你的 accounts.json

```bash
python 02_login.py --import 朋友A.json
```

按 UID 去重；对方的设备号如果格式非法会被清空并提示补真实号。

## 常见问题

### 返回码速查

`claim` 接口的业务返回码（HTTP 都是 200，要看 body 里的 `code`）：

| code | 服务端文案 | 含义 |
|---|---|---|
| `0` | `success` | ✅ 签到成功 |
| `9074` | 当前参与用户太多，请稍后再试 | ⚠️ **文案有误导性**，几乎总是「设备号不对」 |
| `9095` | 当前设备今日已经签到，请明日再来哦～ | ☑️ 这个**设备**今天已签过（不是账号） |
| `1001` / `1002` | — | 🔑 鉴权失败，token 失效，需重新登录 |

### `01_get_device_id.py` 说「找到了 storage.json，但里面没有设备号」

分两种原因：

**1. 客户端确实没登录过。** 先在 Trae 客户端里登录一次，再跑脚本。

**2. 登录过了，但脚本没认出来。** 用记事本打开 `storage.json`，搜索 `icube-dc`，看看后面跟的是什么：

- **是一串数字，但不是 16 位**（比如 15 位）→ 早期版本的校验写死了 16 位，会把它丢掉。升级脚本即可，**位数不影响合法性**。
- **是 UUID / hex（含字母 a-f）** → 那是客户端的旧标识，不是 Aha 号。说明客户端还没把它升级成 Aha 数字号。
- **冒号后面是空的** → 同上。

正常长这样：

```
"iCubeAuthInfo://icube-dc:3124143766407755": { ... }
```

号在**键名**里，不在值里。找到之后直接手抄那个数字，填进 `accounts.json` 的 `deviceId` 就行，不一定非得靠脚本。

### 提示 9074「当前参与用户太多」

这句文案**有误导性**，实际含义几乎总是「设备号不对」。看日志这一行：

```
📱 [设备号] 9876543210987654（配置值）
```

| 来源 | 含义 |
|---|---|
| `客户端真实号` | ✅ 从本机客户端读到并核对过，**能签成** |
| `配置值` | ⚠️ 来自 accounts.json，**无法在本机核实**。如果这个号是编的，必然 9074 |
| `缺设备号` | 脚本会直接停止该账号，提示你去取真号 |

**修法**：在一台装了客户端的机器上跑 `01_get_device_id.py`，把真号填进该账号的 `deviceId`。

其它要排查的：

1. 设备号是不是一串十进制数字（UUID / 32 位 hex 会被忽略）。**位数不限**，15 位、16 位都见过
2. 是不是多个账号共用一个设备号（一设备一天只能签一次，第二个起必然 9095）
3. 时间是不是撞在高峰（避开整点，00:00~00:10 最挤）

日志在 `logs/checkin_YYYY-MM-DD.log`，里面有每次请求的原始响应，排查以它为准。

### 提示 9095「当前设备今日已经签到」

**这个设备号今天已经签过某个账号了。** 不是错误，是限额。

- 如果该账号确实已经签到了 → 正常，明天再来
- 如果该账号**没签过**、是另一个账号用掉了这个号 → 说明设备号配重复了，给每个账号配各自独立的号

### 在同一台机器上换账号，客户端显示「已签到」但其实没签

**这是 Trae 客户端自己的 UI 问题，不是你的配置错。**

`did_checked_in` 是**设备维度**的。机器 A 的签到状态被算在设备上，客户端不管当前登录的是哪个账号，只看这个字段——所以换账号后也会显示"已签到"。

实测过：同一台机器上账号 2 显示"已签到"，实际账号 2 根本没签；换到另一台机器就显示"可签到"并签成功了。

**判断依据以接口返回为准**，别信客户端那个按钮的状态。

### 提示「Token 无效」

token 过期或被别处轮换掉了，重新 `02_login.py --device-id <设备号>` 登录一次即可。

### 脚本会不会把我的 Trae 客户端踢下线？

**不会。** 脚本用的 token 全部来自 `02_login.py` 的独立登录，和桌面客户端那条会话链不是同一条。

`refreshToken` 是按会话签发的，一个账号可以同时存在多条链——手机登着、电脑 IDE 登着、网页版也开着，这就是三条，彼此互不干涉。`02_login.py` 登录一次，等于又开了新的一条。

**只有一种情况会互踢**：把同一份 `refreshToken` 复制到两个地方用。那两条"链"其实是同一条，谁先续期就把对方手里那份作废。

| 场景 | 会不会互踢 |
|---|---|
| 脚本在 NAS / 青龙跑，本机照常开着客户端 | 不会（两条链） |
| 两台机器各自 `02_login.py` 登录一次 | 不会（两条链） |
| 从本机客户端 `storage.json` 里抠 token 拷到 NAS 跑 | **会**（同一条链） |
| 同一份 `accounts.json` 在 NAS 和青龙各跑一份 | **会**（同一条链） |

第一种是绝大多数人的用法，可以放心。

第三种现在**结构上已经不可能发生**：脚本只读设备号、不读 token（设备号写在键名里，连解密都不用），根本拿不到客户端那份 `refreshToken`。

第四种得自己注意——两边要么各 `02_login.py` 登录一次，要么只留一边跑。

踩到互踢的典型表现是**两边交替出问题**：客户端突然要求重新登录、脚本这边正常；过一阵反过来，脚本报「Token 无效」、重新登录就好、几天后又犯。出现这种来回抢的现象，基本就是同一条链被两个地方共用了。

### Windows 上怎么测试？

不用配环境变量，设置都在 `config.json` 里。改完直接跑：

```powershell
cd D:\path\to\trae-checkin
python 03_checkin.py
```

非要临时验某个环境变量，只在当前窗口生效：

```powershell
$env:TRAE_COOLDOWN_MIN = "10"    # PowerShell
set TRAE_COOLDOWN_MIN=10         # cmd
```

### 登录时浏览器一直「认证中」，不跳转怎么办？

**先确认「正常」长什么样** —— 成功时是这样的：

1. 浏览器打开登录链接 → 手机号 + 验证码登录 → 点「登录并使用 Trae」
2. 浏览器**地址栏**变成：

   ```
   http://127.0.0.1:18080/authorize?refreshToken=...&userInfo=...&userJwt=...
   ```

   页面显示「无法访问此网站」——**这是对的**。看地址栏，别看页面。
3. 把地址栏这条链接整条复制下来，粘回终端。

地址栏**没有**变成上面那样、一直停在 `trae.cn` 转圈，就是出问题了。

**最常见原因：回调端口 18080 被别的程序占了**（浏览器把 token 发给了那个程序，脚本收不到）。脚本启动时会自动探测，被占会直接报出 PID：

```
⚠️  回调端口 18080 已被占用（PID 27760）
     taskkill /F /PID 27760
     netstat -ano | findstr :18080    # 复查
```

按提示结束那个进程再重跑即可。常见占用者是**上次没关掉的命令行窗口**，也可能是官方 Trae 客户端。

如果端口确实是空的、还是不跳转：再看一眼**地址栏**（不是页面内容），链接有时已经在那儿了；另外链接有时效，别放太久。

### 今天已经签过了，怎么验证脚本能用？

跑 `python 04_credit_monitor.py --local`，它只查询不签到。能查到余额就说明 token、设备号、接口契约都通了。

### 什么时候签到最容易成功？

避开整点。实测 00:15~00:45 成功率最高，因此推荐 `23 3 * * *`（脚本自身还会再随机抖 0~15 秒）。

## 附录：相比上游修了什么

本项目不是从零写的，而是把社区里若干开源实现攒到一起、逐个定位并修掉它们各自没解决的问题后整理出的版本。最重要的更正是下面第 2 条。

### 1. 请求体 `req_source` 与 token 谱系要对上

Trae 有两个产品谱系，`req_source` 必须与 token 的谱系一致：

| 谱系 | ClientID | req_source |
|---|---|---|
| TRAE | `ono9krqynydwx5` | 1 |
| SOLO | `en1oxy7wnw8j9n` | **2** |

本项目走 SOLO 谱系，所以请求体是 `{"req_source": 2}`。上游不少脚本发 `1` 或空 body。

### 2. 9074 的真正根因：设备号必须是客户端真实注册的 Aha 号

这条是实测出来的，**和社区里流传的"随便编一个数字就行"不一样**。

| 发送的设备号 | `did_checked_in` | `claim` |
|---|---|---|
| 自动生成的数字 | `false` | **9074** |
| 客户端真实 Aha 号 | `true` | **9095**（通过设备检查） |

唯一变量是设备号。**OAuth 登录不会注册设备**，生成号注定失败。上游有脚本的做法是"命中 9074 后换个新设备号重签"——方向完全错了。

而且**限额按设备算**：一个设备一天只能签一次。N 个账号就需要 N 个真实设备号。

本项目据此：不再自动生成设备号（取不到就直接报错）、不给"全局默认设备号"、`02_login.py` 不带 `--device-id` 会明确警告。

### 3. 修掉自己引入的 bug：设备号被误判为「必须 16 位」

这条是**本项目自己的错**，不是上游的问题，单独记一笔免得再犯。

早期版本的 `is_valid_device_id()` 写死了 `len(d) == 16`。结果有使用者的 `storage.json` 里 Aha 号是 **15 位**，`01_get_device_id.py` 读到键名后直接把它丢掉，报"找到了 storage.json，但里面没有设备号"——听起来像"客户端没登录"，实际是本地校验太严。

他自己把校验放宽成 15~16 位后，登录、`ExchangeToken`、签到全部正常。

**说明我们把结论用错了方向**：第 2 条的正确表述是"设备号必须是客户端注册过的那串数字"，其中"16 位"只是**多数机器上的观察，不是规则**。把观察当成规则写进校验，就必然在某台机器上翻车。

现在 `is_valid_device_id()` 只要求是**一串十进制数字**（长度 12~20 作防呆），UUID / 32 位 hex 依然一步被拒。

> 有意思的是，上游 `Trae-AutoCheckin` 的 `dc_device_id()` 本来就只判断 `isdigit()`、不看长度，反而不会踩这个坑。加校验的时候应该更小心一点 —— 严格校验只有在**确实知道约束**的时候才是好事。

### 4. 请求头改回官方客户端的最小集合

只发 `Authorization` / `x-device-id` / `X-User-Region` / `User-Agent`。上游脚本额外编造 `x-os-version`、`x-app-version`、`x-device-type` 等头，反而偏离真实客户端指纹。

### 5. 顺带修掉的两个必崩 Bug

- `pick_batch()` 使用了未定义变量 `size` —— 只要设置 `TRAE_BATCH` 就必崩 `NameError`
- `claim_with_retry()` 有一条分支只返回 3 个值，而调用方解包 4 个 —— 必崩

### 5. Token 轮换链持久化

`refreshToken` 每次续期都会轮换出新值。青龙的环境变量是静态的，不落盘就会"越刷越失效"。续期结果会写回 `accounts.json` 和 `.trae_token_cache.json`。

### 7. 不再从客户端读 token

早期版本会（在装了客户端的机器上）直接读客户端凭据来签到。但那条链和桌面客户端是同一条，脚本一续期就会把客户端踢下线。现在**只从显式配置读账号**，设备号仍然从客户端读（它在键名里，不需要解密）。
